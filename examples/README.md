# 配置分层快速入门

二呆的配置不是一张“大提示词”。运行时按四层合并，越靠前的层级优先级越高：

完整契约可由 Core 读取：`GET /api/v1/config/layers`。它返回每层的责任、存储位置、实际消费点和覆盖关系，适合 WebUI、部署脚本或第三方开源面板直接使用；不要根据页面名称猜测字段归属。

| 层级 | 负责什么 | 后台/API 入口 | 能不能被角色覆盖 |
| --- | --- | --- | --- |
| 公共配置 | 安全边界、能力开关、知识注入、全局回复上限 | `系统设置` / `/api/v1/runtime/config` | 不能放宽 |
| 公共策略 | 默认模型路由、工具目录、媒体与群聊策略 | `运行策略` / `/api/v1/agent-policy-templates` | 实例只能收紧 |
| 角色配置 | 名称、外观、性格、世界观、世界书、样本 | `角色卡` / `/api/v1/personas` | 不改变 Core 安全 |
| 角色策略 | 主动参与、联网触发、搜索表达、角色模型覆盖 | `角色卡 → 运行档案` / `/api/v1/personas/runtime-profiles` | 只能在公共上限内生效 |

实例层在运行中心单独配置：实例配置负责账号、连接器、路由和记忆命名空间；实例策略负责模板与当前实例 overrides。它们不会修改角色卡，也不会污染另一实例的记忆。

### 合并规则

公共层先提供默认值，角色层再覆盖同名且已填写的字段，实例层最后覆盖。空字段继续继承，不会因为表单未填写而清空上层值。安全边界、管理员权限和媒体硬上限不能由角色或普通实例放宽。

开源接入方只需要实现三件事：读取 `/api/v1/config/layers` 展示分层；按 `precedence` 合并可覆盖字段；把密钥留在服务端环境变量中，仅提交 `credentialRef`。

推荐的第一次配置顺序：

1. 先在系统设置确认公共安全和能力上限。
2. 建一个公共策略模板，选择聊天、任务、判断和工具默认值。
3. 导入或创建角色卡，再填写角色运行档案。
4. 在运行中心创建实例，绑定角色、策略模板和平台连接器。

## 搜索策略示例

`searchMode=explicit_only` 不是关闭搜索。它表示只有“帮我查、搜索、网上看看、给出处”等明确意图才搜索，避免陪伴型角色把每句闲聊都变成百科问答。

`searchReplyStyle=natural` 表示搜索结果只作为角色的内部参考，最终仍由当前角色用自己的口吻归纳；不会直接把标题、来源列表和 URL 丢进群里。

示例文件：

- `roles/doubao.runtime.json`：客服型角色，允许明确搜索和 OPS 查询。
- `roles/xiaoman.runtime.json`：陪伴型角色，默认不主动搜索，被明确要求时才查，并用真人口吻归纳。

这些文件只包含可公开的配置，不包含账号、密码、API Key 或环境变量值。

## 从源码启动

1. 复制 `runtime.env.example` 为服务器上的 `runtime.env`，只在服务器填写令牌和 `credentialRef` 对应的环境变量。
2. 启动 Core 后打开后台的“运行中心”，先创建策略模板，再创建运行实例。
3. 用 `GET /api/v1/config/layers` 检查自己的 WebUI 或插件是否跟随当前分层契约。

不要把 `runtime.env`、SQLite 数据库、媒体目录或真实账号会话提交到公开仓库。
